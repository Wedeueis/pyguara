    pyguara.common.types

    Foundational value types for the PyGuara engine.

    Vector2, Color and Rect are the primitives every other subsystem shares. Vector2 is implemented in the native extension; the class body here is its signature for type checkers. Color and Rect are plain dataclasses; no rendering backend is imported here.

    Y increases downwards, matching SDL and the engine's default gravity, so "up" is negative Y. Every direction helper here and in Transform follows that.

    Coordinate module-attribute 

    Coordinate = tuple[float, float] | list[float] | Vector2

    Anything accepted where a 2D coordinate is expected.

    Vector2

    An immutable 2D vector for positions, velocities and directions.

    Implemented in Rust. Components are always floats. It unpacks, indexes and has a length of 2 like the (x, y) tuple it equals and hashes as. Every method returns a new vector.

    Color dataclass

    An RGBA colour, one byte per channel.

    A backend-agnostic value type. Channels are coerced to int and clamped to 0-255 on construction, so colour arithmetic that overshoots -- a fade, a brightness multiplier, an out-of-range HSV conversion -- saturates instead of handing a backend a value it cannot represent.

    Attributes:

    Name Type Description
    r int

    Red channel, 0-255.
    g int

    Green channel, 0-255.
    b int

    Blue channel, 0-255.
    a int

    Alpha channel, 0-255. Defaults to fully opaque.

    normalized property 

    normalized: tuple[float, float, float, float]

    The channels as floats in 0.0-1.0, for shaders and GL backends.

    Rect dataclass

    An axis-aligned rectangle in integer pixel coordinates.

    A backend-agnostic value type. Mutable, matching pygame.Rect, because the UI layout engine assigns to rect.x and friends in place.

    Attributes:

    clip 

    clip(other: Rect) -> Rect

    Return the overlapping region of this rectangle and other.

    When they do not overlap the result is zero-sized at this rectangle's own position, which is what pygame.Rect.clip does. Verified differentially rather than assumed: the first version of this returned Rect(0, 0, 0, 0), which agrees with pygame only for a rectangle that happens to sit at the origin -- and the probe that "confirmed" it used exactly such a rectangle.

    Test colliderect() first to tell "no overlap" from "an empty overlap", since a zero-sized result is the answer to both.
