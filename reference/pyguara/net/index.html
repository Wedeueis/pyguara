    pyguara.net

    Networked multiplayer: a listen server and the players who join it.

    Opt-in, so a single-player game imports none of this. Importing it is always safe, even with no native extension. A session is what needs one, and fails with a clear message when it starts.

    Everything arriving from the network is untrusted. The Rust core authenticates packets and survives hostile ones, but it does not make a decoded value sensible, so code above this package bounds-checks lengths, ids and enums itself. See docs/systems/networking.md.

    CommandSchema

    How a game's command is packed. Both sides must build the same one.

    Keep commands small, since one goes out every tick, and frozen, since they're held for replay:

    CommandSchema(Move, x=Quantised(step=1 / 64), y=Quantised(step=1 / 64))

    PredictionClient

    A client's side: runs its own character now, and corrects from the host.

    Attributes:

    Name Type Description
    malformed

    State messages that could not be read, which are dropped.
    stale_states

    State messages older than one already seen, which are dropped.
    unsent_commands

    Command messages the transport would not accept.
    corrections

    How many times a host state moved the character.
    last_correction

    How far the most recent one moved it, in world units.
    largest_correction

    The largest so far, in world units.
    replayed_ticks

    Ticks simulated again because of corrections.
    tick_adjustments

    How many times the lead over the host was changed.
    advances

    How many times the character has been advanced, replays included. It changes as each advance begins, so whatever numbers what an advance does can tell a replay of a tick from more of the same tick.

    tick property 

    tick: int | None

    The host tick being predicted, or None before there's a character to predict.

    advancing property 

    advancing: int | None

    The host tick the character is stepping through, while its advance runs.

    Read it from inside advance, to act as the host does on that tick, such as firing a shot numbered by it. tick can't tell you: one step may advance several ticks to catch up, and a correction replays past ones from inside handle_message. None outside an advance.

    Replicated dataclass

    Bases: StrictComponent

    Marks an entity for the host to replicate.

    Attributes:

    Name Type Description
    prefab str

    The name clients create it from, through their spawners. At most 64 bytes: one that can't be sent is refused and counted in unreplicated.
    owner int | None

    The player slot that alone may see it, or None for everyone. Per-player drops use this.
    controller int | None

    The player slot whose character this is. Only that client is told, and it predicts the entity rather than drawing it from snapshots. Set it before the entity's first snapshot: a later change isn't sent.

    ReplicationClient

    A client's side: applies what the host sent, on a delayed timeline.

    Spawners are named in advance, so a name from the network can only ever choose among them. It is never a path to load.

    Attributes:

    Name Type Description
    malformed

    Messages that could not be read, which are dropped.
    stale_records

    Records older than one already seen, which are dropped.
    unknown_records

    Records for an entity with no spawn yet, which are dropped.
    digests_matched

    State hashes that agreed with the host.
    digests_mismatched

    State hashes that did not. Above 0 is a real desync.
    digests_skipped

    Hashes that could not be compared, because of loss.
    failed str | None

    Why this client has stopped applying anything, or None.

    render_tick property 

    render_tick: float | None

    The host tick currently being drawn, or None before anything has arrived.

    UdpTransport

    Bases: NativeTransport

    A Transport over a real UDP socket, driven by a Rust thread.

    The thread acknowledges, resends and sends keepalives without the GIL, so a stalled Python frame delays game state and not the connection.
