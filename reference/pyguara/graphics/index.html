    pyguara.graphics

    Graphics: the rendering pipeline, its components, and the backends.

    Re-exported here so the rendering surface is reachable without knowing which submodule each name lives in. from pyguara.graphics import Sprite, Camera2D, RenderSystem used to find nothing at all -- only the nine-patch helpers were exported -- which made the whole package undiscoverable without reading it.

    Backends are deliberately absent: importing this must not pull in pygame or the native renderer. Reach for pyguara.graphics.backends.<name> when you mean a specific one, and otherwise take IRenderer from the DI container.

    AnimationSystem

    System that automatically updates all animation components.

    Processes all entities with Animator or AnimationStateMachine components, advancing each one every frame. Both components are pure data; the advancing is advance_state_machine / advance_animator, the free functions that live beside them.

    Compatible with SystemManager's update(dt) signature.

    Data for a single animation state (e.g., 'walk_down').

    Animator

    Bases: StrictComponent

    Component that manages playback of AnimationClips.

    It 'drives' a Sprite component. Every frame, it calculates which texture frame should be visible and assigns it to the Sprite.

    Holds the clip table and the playback cursor; the behaviour that moves that cursor lives beside this class as free functions, and AnimationSystem is what calls them each frame. See "Playback" below.

    Camera2D

    A 2D Camera component that defines the viewable area of the game world.

    It handles Zoom and Panning math. It does NOT render anything; it simply provides the transformation the renderer applies.

    There is one world-to-screen transform: screen = world * zoom + screen_offset(viewport). world_to_screen, screen_to_world and get_view_bounds are built on it. Rotation is not supported.

    Attributes:

    Name Type Description
    position Vector2

    The center of the camera in World Coordinates.
    zoom float

    The scale factor (1.0 = 100%, 2.0 = 200%).

    position property writable 

    position: Vector2

    The centre of the camera in world coordinates.

    While a view override is held this is the override, so that a game drawing by hand from camera.position follows the editor's view exactly as the render pipeline does. The game's own writes keep landing underneath, where release_view finds them.

    view_overridden property 

    view_overridden: bool

    Whether something other than the game is driving the view.

    view_position property 

    view_position: Vector2

    Where the camera actually looks this frame.

    position plus the current shake displacement. Every transform -- screen_offset, and get_view_bounds through it -- is expressed against this, not against position, so a shake moves the picture without moving the camera: position stays the value follow(), frame_targets() or the game last set, and bounds clamping has a stable thing to clamp.

    bounds property 

    bounds: Rect | None

    The world box the view is kept inside, or None for unbounded.

    zoom property writable 

    zoom: float

    The scale factor: 1.0 is natural size, 2.0 twice as large.

    The override while one is held, for the same reason position is.

    take_view 

    take_view(
    position: Vector2 | None = None,
    zoom: float | None = None,
) -> None

    Drive the view from outside the game.

    What an editor does when a person pans or zooms: Godot's 2D editor view and Unity's Scene view are not the game's camera, and the reason is this -- a camera the game writes every tick cannot also be navigated by hand.

    Idempotent, so a drag can call it on every frame without having to track whether it already holds the view.

    Parameters:

    Name Type Description Default
    position Vector2 | None

    Where to look, or None to take the current position.

    		 None
    zoom float | None

    The scale, or None to take the current one.

    		 None

    Raises:

    Type Description
    ValueError

    If zoom is not positive.

    release_view 

    release_view() -> None

    Hand the view back to the game.

    Batcher

    Group sorted render commands into draw batches.

    Consecutive commands sharing a texture and a material become one batch, so a backend issues one draw call per group. Rotation, scale, tint and atlas source rect are optional parallel columns, filled only from the first command in a batch that needs one.

    Grouping is by material_id, not object identity, so a copied or deserialised material batches with its original. The loop works on floats, not Vector2; see docs/guides/performance.md.
