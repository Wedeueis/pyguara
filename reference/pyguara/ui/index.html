    pyguara.ui

    Standard UI Components and Theming.

    KeyboardEditable

    Bases: Protocol

    A widget that needs the modifier keys held with a keypress.

    An optional capability, tested with isinstance, like TextInsertable and Scrollable; UIElement.handle_event() keeps its three-argument form.

    Only presses route here. A release arrives as UIEventType.KEY_UP through handle_event.

    Scrollable

    Bases: Protocol

    A widget that can scroll its own contents.

    An optional capability, tested with isinstance; UIElement.handle_event() keeps its three-argument form.

    UIManager routes a wheel event by hit-testing the cursor and walking up from whatever is under it to the nearest Scrollable, so a wheel over a button inside a list scrolls the list.

    TextInsertable

    Bases: Protocol

    A widget that accepts composed text.

    An optional capability, tested with isinstance, rather than a text parameter added to UIElement.handle_event(). Widening that signature would break every widget -- in this engine and in any game -- that already implements the three-argument form, and only text fields have any use for it.

    Same shape as the storage capabilities in pyguara/persistence: the base contract stays minimal and a widget opts in.

    UIBuilder

    Builds a UI tree, tracking the current parent on a stack.

    Single use: build one tree, mount it, discard the builder. Demos rebuild their menus from scratch on every on_resume(), so reuse would buy nothing and a half-reset builder is a worse failure than a clear error.

    roots property 

    roots: list[UIElement]

    The top-level elements built, in creation order.

    current property 

    current: UIElement | None

    The element children are currently being added to, if any.

    ColorScheme dataclass

    Standardized color palette using Color objects.

    Two layers. The base five colours plus two overlays are the shorthand a theme is written in. The semantic roles below them (surfaces, a text hierarchy, edges, action states) are what components read.

    Every semantic role the caller does not name is derived from the base colours. derive() also refuses an unknown role by name; the presets and pyguara.ui.design_system build theirs with it.

    ShadowScheme dataclass

    Shadow effect configuration.

    enabled, offset_x, offset_y and color are consumed by Widget.draw_shadow() (and so by Button and Panel) and by the design system's BevelButton.

    blur is not honoured: shadows are hard-edged rectangles. The field stays because themes serialize it.

    Attributes:

    Name Type Description
    enabled bool

    Whether widgets draw a shadow at all. Off in every preset.
    offset_x int

    Shadow offset to the right, in pixels.
    offset_y int

    Shadow offset downwards, in pixels.
    blur int

    Declared but unconsumed; see above.
    color Color

    The shadow colour, usually translucent black.
